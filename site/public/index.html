One setup.

A 3-2-1 backup without writing a script.

  1. Your folders

    Pick folders in the taskbar panel or with r2b add. A local index means only what changed gets sent.

  2. Drime Primary backup

    Uploads run in parallel and adjust to what the server allows. Your files stay browsable in the Drime web app.

  3. S3 storage Secondary backup

    After every run a copy goes to R2, B2, Amazon S3 or any S3 storage. Ultra fast mode copies cloud to cloud.

The more files, the further ahead.

r2backup 1.5.0 against rclone 1.75.0 on Drime, same data and connection, November 2026. rclone ran at --transfers 16, its fastest setting there.

Is everything fine?
Know in two seconds.

Click the icon next to the clock. Green ticks: your folders are backed up. Amber: it is waiting. Red: it needs you, and it says why in plain words.

  • Back up now, add a folder, restore: one click each
  • Pause and resume; an interrupted run picks up where it stopped
  • Deleted and overwritten files kept for 30 days
  • Updates itself when you open the panel

Built for the backups people actually have.

Fast with many small files

Code folders, notes, photo libraries. Thousands of small files go up in parallel, not one at a time.

Catches same-size edits

Drime keeps no file dates, so size-only tools skip a file edited in place. r2backup checks its own index and sends it.

20 of 20 such edits backed up in the benchmark; rclone's default caught 0.

Already use the Drime app?

Choose Secondary backup only and r2backup copies your Drime folders to S3 storage, with a second company.

Plain files, not a vault

Your storage holds your folder as normal files you can open anywhere. No pack format to get locked into.

Survives real life

A Wi-Fi drop holds the run instead of failing it. Sleep, pause, resume: finished files are checkpointed as it goes.

Terminal too, if you want it

One r2b program with a full terminal app on Windows, macOS and Linux. Same features as the panel.
